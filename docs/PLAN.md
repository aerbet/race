# PLAN — план разработки

Порядок жёсткий: сначала доказываем, что управление ощущается как надо (фазы 0–1), и только потом тратим силы на города, онлайн и метаигру. Каждая задача: согласовать план с владельцем → сделать → тесты → отметить `[x]` → записать решения в `DECISIONS.md`.

Обозначения: **Готово, когда** — критерий приёмки задачи. **Контрольная точка** — решение владельца «продолжаем или переделываем».

---

## Фаза 0. Скелет и полигон (≈ 1 неделя)

- [x] **0.1 Монорепозиторий.** pnpm workspaces: `apps/client`, `packages/shared`, `packages/physics`. TypeScript strict, ESLint, Prettier, Vitest. Файлы `docs/DECISIONS.md`, `docs/ASSETS.md`.
  Готово, когда: `pnpm install && pnpm lint && pnpm test` проходят на чистом клоне.
- [x] **0.2 Клиент.** Vite + Three.js: сцена, камера, свет, ресайз, счётчик FPS. Пресеты качества `low` / `high` (переключатель в URL `?q=low`).
  Готово, когда: пустая сцена 60 fps на ПК, открывается на телефоне.
- [x] **0.3 Игровой цикл.** Фиксированный шаг 60 Гц (аккумулятор времени), рендер с интерполяцией между шагами, пауза при скрытой вкладке.
  Готово, когда: тест — 10 секунд симуляции дают одинаковое число шагов при 30/60/144 вызовах рендера в секунду.
- [x] **0.4 Ввод.** Единый слой ввода: клавиатура, Gamepad API, сенсорные кнопки. Значения `throttle`, `brake`, `steer`, `handbrake`, `nitro` в диапазоне 0..1 (руль −1..1). Плавное доведение руля для клавиатуры. Запись ввода по шагам.
  Готово, когда: отладочная панель показывает значения всех устройств; запись → воспроизведение даёт тот же поток значений.
- [x] **0.5 Полигон.** Плоскость 1×1 км, тестовая трасса из примитивов: длинная прямая, шпилька, связка S-поворотов, широкий дрифт-круг, трамплин, стена вдоль дороги. Rapier подключён, коллизии со стеной работают.
  Готово, когда: по полигону можно ездить кубом-заглушкой.

## Фаза 1. Машина и «ощущение» (≈ 4–5 недель) — самая важная

- [x] **1.1 Формат конфига машины** (`packages/shared/src/cars/schema.ts` + zod-валидация): масса, центр масс, геометрия колёс, подвеска (жёсткость, демпфер, ход), кривая мощности по оборотам, передачи, кривые сцепления (продольная/боковая), параметры всех помощников, нитро. Два стартовых конфига: `era2000_coupe.json`, `era2026_hatch.json`.
  Готово, когда: невалидный конфиг падает с понятной ошибкой (тест).
- [x] **1.2 Raycast vehicle** в `packages/physics`: 4 луча подвески, силы пружин и демпферов, продольная и боковая сила шин по кривым, привод (задний/полный), автомат и ручная коробка.
  Готово, когда: тесты — разгон 0–100 км/ч в пределах ±10 % от значения конфига; машина стоит на месте без дрейфа; на прямой без руля не уводит.
- [x] **1.3 Аркадные помощники** из `SPEC.md` (руль по скорости, помощь в повороте, срыв и удержание дрифта, выход из дрифта, стабилизация в воздухе, мягкие стены, автосброс через 3 с). Каждый включается флагом в конфиге.
  Готово, когда: тест-бот по записанному вводу проходит дрифт-круг с углом заноса 20–55° без разворота; при выключенных помощниках поведение заметно отличается (для сравнения).
- [x] **1.4 Нитро:** заряд от дрифта, обгона и прыжка; расход; +25–40 % тяги.
- [x] **1.5 Камера:** пружина, отставание в поворотах, FOV 65→85, тряска на скорости, три вида. Линии скорости и размытие — только в пресете `high`.
- [x] **1.6 Отладка ощущений:** панель lil-gui со всеми параметрами текущей машины «на лету», сохранение пресета в JSON, телеметрия (скорость, обороты, угол заноса, нагрузка на колёса) графиком поверх экрана.
- [x] **1.7 Детерминизм:** запись ввода → повтор с разным FPS рендера → расхождение времени круга < 1 %.
- [x] **1.8 Заглушки графики:** простые low-poly кузова (собственные или CC0, запись в ASSETS.md), колёса крутятся и поворачиваются, след и дым от шин при заносе.
- [x] **1.9 Звук двигателя:** Web Audio, кроссфейд 3–4 сэмплов по оборотам (CC0 или собственная запись), турбо-сброс, визг шин по скольжению.
- [x] **1.10 Сборка для слепого теста:** страница выбора машины + полигон + форма оценки (5 вопросов, 1–5) с сохранением результатов в JSON-файл для скачивания.

**Контрольная точка 1:** слепой тест на 10–20 игроках, средняя ≥ 4,0 по каждому пункту. Пока не выполнено — дорабатываем 1.2–1.5, дальше не идём.

## Фаза 2. Трасса и одиночная гонка (≈ 2–3 недели)

- [x] **2.1 Формат трассы** (`packages/shared/src/tracks/`): сплайн маршрута, ширина, чекпоинты (плоскости), стартовая решётка, тип (`sprint` / `circuit` / `drift`), число кругов.
- [x] **2.2 Гоночная логика:** обратный отсчёт, порядок чекпоинтов, круги, финиш, позиции, неправильное направление, сброс на последний чекпоинт.
- [x] **2.3 Режимы:** спринт, круг, дрифт (очки за угол × скорость × длину цепочки, множитель, сброс при ударе), заезд на время.
- [x] **2.4 Призраки:** запись позиции и поворота 20 раз в секунду, сжатие, сохранение в localStorage, гонка против своего призрака.
- [x] **2.5 Боты:** следование по гоночной линии из сплайна, торможение перед поворотами по кривизне, 3 уровня сложности. Притяжение к лидеру — только для карьеры (флаг).
- [x] **2.6 HUD:** спидометр, передача, нитро, позиция, круг, время, мини-карта. Собственный визуальный стиль (не копировать интерфейсы других игр).

**Контрольная точка 2:** гонка против 5 ботов на полигонной трассе проходится от старта до финиша без багов; телефон держит 30 fps на `low`.

## Фаза 3. Онлайн-прототип (≈ 3–4 недели)

- [x] **3.1 Решение по серверу** (Colyseus или чистый `ws`) — записать в DECISIONS.md с аргументами.
- [x] **3.2 Протокол** в `packages/shared/src/net/`: сообщения входа в комнату, ввод/состояние, события гонки. Бинарная сериализация (например, через DataView), версия протокола.
- [x] **3.3 Комната гонки** (`apps/race-server`): до 8 игроков, тик 20–30 Гц, старт, чекпоинты и финиш считает сервер.
- [x] **3.4 Клиентская сеть:** предсказание своей машины с мягкой коррекцией, интерполяция чужих (буфер 100 мс), экстраполяция при потере пакетов.
- [x] **3.5 Проверки правдоподобия** на сервере (скорость, телепорты, время участка) — тесты на подделанных пакетах.
- [x] **3.6 Симулятор плохой сети:** задержка, джиттер, потери настраиваются в dev-режиме.
- [x] **3.7 Приватная комната по ссылке** и быстрый поиск; боты добавляются через 30 с ожидания.

**Контрольная точка 3:** 4 игрока при искусственном пинге 150 мс и 2 % потерь проходят гонку без заметных рывков; спорных финишей нет.

## Фаза 4. Вертикальный срез города (≈ 6–8 недель, нужен 3D-художник)

- [x] **4.1 Инструмент `tools/osm-to-city`:** выгрузка района из OpenStreetMap → упрощённая дорожная сеть → разбиение на блоки 256 м → glTF. Атрибуция OSM в игре.
- [x] **4.2 Модульная застройка:** набор зданий региона, процедурная расстановка вдоль улиц.
- [x] **4.3 Стриминг блоков** и LOD; бюджет размера (страна ≤ 80 МБ), KTX2 + meshopt.
- [x] **4.4 Ночь и погода:** фонари, неон, мокрый асфальт (`high`), снег/слякоть для «России»; влияние покрытия на сцепление.
- [x] **4.5 Свободная езда** по району с другими игроками (до 16), вызов на гонку фарами.
- [x] **4.6 Трассы внутри города:** 3 трассы на одном районе «России».

**Контрольная точка 4:** тест на 50–100 игроках из целевой аудитории; 30 fps на целевом телефоне.

- [x] **5.2 Профиль и гараж:** машины, детали, PI и класс, визуальный тюнинг (сохранение конфигурации).
