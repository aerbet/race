# BLENDER_PLAN — как Claude делает 3D: машины, города, трассы

Художника нет — модели строит Claude Code в Блендере. Этот документ — полный порядок работы: установка, структура папок, конвейеры для машин, города и трасс, чек-листы приёмки и готовые промпты.

Технические требования к результату (полигоны, текстуры, имена узлов, правила «двойников») — в `docs/ART_BRIEF.md`. Если документы расходятся, прав ART_BRIEF.

---

## 0. Что реально получится

Claude не рисует руками, как художник. Он пишет Python-скрипты для Блендера (`bpy`), которые строят модель из параметров, рендерит картинки, смотрит на них и исправляет скрипт. Плюсы: модели чистые, лёгкие, одинаковые по качеству, любую можно пересобрать за минуту, кузовные киты и LOD получаются автоматически. Ограничение: уровень AAA-фотореализма не получится.

Поэтому выбран стиль **«стилизованный реализм»**: чёткие, слегка упрощённые формы, глянцевая краска с яркими бликами, детали фар, решёток и воздухозаборников — геометрией и светящимися материалами, мелкие швы — картой нормалей. Ночь, неон и мокрый асфальт делают остальное. Так выглядят многие современные инди-гонки, и это лучше, чем недоделанный фотореализм.

Честная оценка времени (сессии Claude Code с вашими проверками): первая машина целиком — 3–5 дней итераций (пока отлаживается генератор), каждая следующая — 1–2 дня, набор зданий для одного города — 1–2 недели.

## 1. Установка (на ноутбуке, один раз)

На телефоне Блендер не работает, поэтому 3D-задачи Claude Code выполняет на ноутбуке.

1. **Блендер 4.2 LTS или новее LTS** — https://www.blender.org/download/ (бесплатно). Запомните путь к программе.
2. Переменная окружения `BLENDER_BIN` с этим путём:
   - Windows: `setx BLENDER_BIN "C:\Program Files\Blender Foundation\Blender 4.2\blender.exe"`
   - macOS: `export BLENDER_BIN=/Applications/Blender.app/Contents/MacOS/Blender` (в `~/.zshrc`)
3. **Node.js 22 и pnpm** (уже нужны для игры).
4. **gltf-transform** (сжатие моделей): ставится в репозиторий как dev-зависимость `@gltf-transform/cli`.
5. **KTX-Software** (`toktx`, для текстур KTX2) — https://github.com/KhronosGroup/KTX-Software/releases.
6. **Claude Code** на ноутбуке в папке репозитория.
7. **Необязательно — Blender MCP** (живое управление открытым Блендером, скриншоты вьюпорта). Аддон из https://github.com/ahujasid/blender-mcp, затем в терминале: `claude mcp add blender uvx mcp-for-blender` (в старых версиях пакет назывался `blender-mcp`). В Блендере: клавиша `N` в 3D-окне → вкладка MCP → Start Server. Используется только для доводки — основная работа идёт скриптами (см. раздел 2).

Проверка: `"%BLENDER_BIN%" --version` (Windows) или `$BLENDER_BIN --version` выводит версию.

## 2. Как Claude работает с Блендером

**Режим А — скрипты в фоне (основной).** Claude запускает Блендер без окна:

```bash
$BLENDER_BIN -b --factory-startup -P art/scripts/cars/build_car.py -- --spec art/specs/cars/kaizen_rx34.json
```

Скрипт строит модель с нуля, сохраняет `.blend`, экспортирует `.glb` и рендерит превью. Всё лежит в репозитории, поэтому любой результат можно пересобрать, сравнить и откатить.

**Режим Б — Blender MCP (доводка).** Claude видит открытую сцену и меняет её вживую — удобно подогнать изгиб капота. **Правило:** каждая такая правка сразу переносится в спецификацию или скрипт, иначе при следующей сборке она пропадёт.

**Как Claude «видит» модель.** После каждой сборки скрипт рендерит PNG-картинки в `art/renders/<id>/`. Claude открывает их и проверяет по чек-листу. Вы получаете те же картинки и отвечаете «ок» или что поправить.

## 3. Структура папки `art/`

```
art/
├─ README.md                  # как собрать всё, ссылки на этот план
├─ scripts/
│  ├─ lib/                    # общее: сброс сцены, материалы, UV, LOD, экспорт, рендер, проверки
│  │  ├─ scene.py  materials.py  uv.py  lod.py  export.py  render.py  checks.py
│  ├─ cars/
│  │  ├─ build_car.py         # кузов + стёкла + фары + решётки + сокеты по спецификации
│  │  ├─ kits.py              # кузовные киты (бамперы, пороги, спойлеры, капоты)
│  │  ├─ wheels.py            # диски и шины
│  │  └─ silhouette.py        # схема силуэта (вид сбоку/сверху/спереди) в SVG/PNG для сверки
│  ├─ city/
│  │  ├─ build_modules.py     # здания-модули по параметрам
│  │  ├─ props.py             # фонари, остановки, ограждения, щиты, светофоры
│  │  ├─ landmarks.py         # стилизованные ориентиры
│  │  └─ trim_sheet.py        # общий атлас текстур фасадов + атлас ночных окон
│  └─ track/
│     ├─ dressing.py          # заборы, шинные стенки, трибуны, баннеры, арки
│     └─ terrain.py           # рельеф вокруг горной трассы
├─ specs/
│  ├─ cars/<id>.json          # параметры машины (раздел 4.1)
│  ├─ wheels/*.json
│  └─ city/<kit>.json         # параметры набора зданий и список ориентиров
├─ renders/<id>/              # превью для проверки (в git — только последняя версия)
├─ source/                    # .blend (в .gitignore — пересобираются из скриптов)
└─ export/                    # итоговые .glb перед сжатием (в .gitignore)
```

Готовые сжатые модели копируются в `apps/client/public/cars/<id>/` и `apps/client/public/cities/<kit>/`.

Команды в `package.json` (задача B0):

| Команда | Что делает |
|---|---|
| `pnpm art:car <id>` | Собрать машину по спецификации, экспорт, сжатие, рендеры |
| `pnpm art:car:all` | Пересобрать все машины |
| `pnpm art:wheels` | Собрать все диски |
| `pnpm art:city <kit>` | Собрать набор зданий и реквизита |
| `pnpm art:render <id>` | Только рендеры |
| `pnpm art:validate` | Проверить все модели валидатором |

## 4. Общие правила для всех моделей

- 1 юнит = 1 метр. В Блендере нос машины смотрит по **+Y**, верх +Z; экспортёр glTF переводит это в −Z «вперёд» и +Y «вверх», как в игре.
- Все объекты и материалы — по именам из ART_BRIEF. Никаких «Cube.001».
- Модификаторы перед экспортом применяются, трансформы обнуляются (Apply All Transforms).
- Нормали — наружу, без дублирующихся вершин, без вырожденных граней (проверка в `checks.py`).
- Материалы — PBR (Principled BSDF): base color, metallic/roughness, normal, emission. Никаких нод, которые не переживут экспорт в glTF.
- Текстуры генерируются процедурно в Блендере (шейдерные ноды → запекание в изображение), без скачанных фото.
- Экспорт: glTF Binary (`.glb`), Y-up, Apply Modifiers, без камер и источников света. Затем `gltf-transform`: meshopt, KTX2 (цвет — ETC1S, нормали — UASTC), проверка размера.
- Ни одного реального логотипа, названия бренда или узнаваемой надписи — ни на машинах, ни на щитах.

## 5. Машины

### 5.1 Спецификация машины `art/specs/cars/<id>.json`

Каждая машина описывается параметрами, а не лепится руками:

```json
{
  "id": "kaizen_rx34",
  "displayName": "Kaizen RX-34",
  "era": "2000",
  "reference": "Дух японского турбо-купе конца 90-х (справка, в игру не попадает)",
  "dimensions": { "length": 4.60, "width": 1.79, "height": 1.36, "wheelbase": 2.67, "trackFront": 1.48, "trackRear": 1.49, "groundClearance": 0.13, "wheelDiameter": 0.66 },
  "profile": {
    "side": [[0.00, 0.30], [0.04, 0.52], [0.30, 0.66], [0.38, 1.00], [0.72, 1.00], [0.86, 0.74], [1.00, 0.62]],
    "plan": [[0.00, 0.80], [0.08, 0.96], [0.25, 1.00], [0.80, 1.00], [0.96, 0.94], [1.00, 0.84]],
    "section": { "exponent": 3.2, "tumblehome": 0.12, "shoulder": 0.55 }
  },
  "greenhouse": { "aPillar": 0.34, "cPillar": 0.74, "roofSag": 0.01, "windowLine": 0.62 },
  "arches": { "front": { "radius": 0.37, "flare": 0.02 }, "rear": { "radius": 0.38, "flare": 0.03 } },
  "face": { "headlight": "slim_wedge", "grille": "low_mesh_wide", "intakes": "triple" },
  "rear": { "taillight": "twin_round", "diffuser": "subtle", "exhaust": "twin_round" },
  "lines": ["shoulder_crease", "door_kick"],
  "differences": [
    "фары — узкий клин вместо оригинальной формы",
    "решётка — низкая широкая сетка, без фирменной формы",
    "задние фонари — сдвоенные кольца другого диаметра и расстановки",
    "боковой воздухозаборник за передним колесом",
    "своя форма зеркал и задней стойки"
  ],
  "budget": { "lod0": 40000 },
  "paint": { "default": "#1f4fd1", "finish": "metallic" }
}
```

- `dimensions` — из открытых технических характеристик референса, округлить и изменить на 1–3%.
- `profile.side` — верхняя линия кузова сбоку (доля длины → доля высоты), `plan` — ширина сверху, `section` — форма поперечного сечения (суперэллипс), `tumblehome` — завал боковин к крыше.
- `face`, `rear`, `lines` — выбор из библиотеки элементов (`build_car.py`), которую Claude пополняет новыми вариантами по мере работы.
- `differences` — **обязательно минимум 4 пункта**, это юридическая защита «двойника».

### 5.2 Конвейер одной машины

1. **Схема силуэта.** `silhouette.py` рисует виды сбоку, сверху и спереди по спецификации (SVG + PNG). Claude сравнивает с тем, как должен выглядеть типаж, правит кривые. *Стоп: владелец утверждает силуэт.*
2. **Кузов.** Лофт поперечных сечений вдоль длины: 48–64 сечения × 32–48 точек → сетка из четырёхугольников → подразделение (Subdivision 2) → форма. Арки — булевым вычитанием цилиндров + расширение крыльев по `flare`. Линии (`lines`) — канавки через ребро с фаской.
3. **Остекление.** Выделение зоны `greenhouse` → отдельный объект `glass`, отступ внутрь на 5 мм, рамки окон.
4. **Лицо и корма.** Фары, фонари, решётки и воздухозаборники — из библиотеки элементов, вписываются в поверхность кузова (shrinkwrap), материалы со свечением для фар.
5. **Детали.** Зеркала, ручки, выхлоп, днище-заглушка, упрощённый салон (`interior_low`).
6. **Разбиение на узлы** по ART_BRIEF: `body`, `hood`, `bumper_front`, `bumper_rear`, `skirts`, `spoiler`, `glass`, `lights_front`, `lights_rear`, `exhaust`, `interior_low`; пустые объекты `socket_*`.
7. **Высокополигональная копия → запекание.** Копия с Subdivision 3 и острыми швами → запекание карт нормалей и AO на рабочую модель (2048 для кузова).
8. **UV.** `uv0` — Smart UV Project с отступом 4 px; `uv1` — развёртка под ливреи: левый бок, правый бок, капот + крыша, перед, зад — крупными островами в своих зонах атласа, без искажений (проверка шахматкой на рендере).
9. **Маска покраски.** Текстура: R — основной цвет, G — второй цвет, B — хром/карбон (по материалам деталей).
10. **Бюджет и LOD.** Decimate до бюджета LOD0 (25–45 тыс. треугольников), LOD1 ≈ 40%, LOD2 ≈ 10%. Суффиксы `_LOD1`, `_LOD2`.
11. **Экспорт и сжатие.** `.glb` → `gltf-transform` (meshopt, KTX2) → `apps/client/public/cars/<id>/base.glb`.
12. **Рендеры** (раздел 5.5) → самопроверка по чек-листу (5.6) → *стоп: владелец утверждает по картинкам*.
13. **Проверка в игре:** загрузка, посадка колёс в арках, свет фар, 30 fps на телефоне в пресете `low`.

### 5.3 Колёса — `wheels.py`

6 дисков по параметрам: число спиц (5–10), форма спицы (прямая, двойная, сетка, турбина, «пятилучевая звезда», «многоспицевый» дизайн), глубина вылета (dish), цвет и отделка. Каждый диск в двух диаметрах. Шина — профиль по ширине и высоте, протектор картой нормалей, **без надписей**. Узлы `wheel_FL/FR/RL/RR` (вращаются), `brake_*` (суппорт и диск, не вращаются). Бюджет: колесо ≤ 3 тыс. треугольников.

### 5.4 Кузовные киты и образы — `kits.py`

Для каждой машины 3 кита: «Уличный» (аккуратные губа и пороги), «Трековый» (сплиттер, диффузор, большое антикрыло), «Дрифт» (широкие арки, вынос, утиный хвост). Кит заменяет `bumper_front`, `bumper_rear`, `skirts`, `spoiler`, `hood` и крепится по сокетам; `body` не меняется (иначе не сойдутся ливреи). Генерация — от тех же сечений, что и кузов, со смещением и добавками, поэтому детали прилегают без щелей.

«Легендарный образ» = кит + ливрея + диски + цвет + неон + дым, описывается JSON-ом в `packages/shared/src/shop/looks/*.json`, 3D-моделей не требует.

### 5.5 Рендеры для проверки

`render.py` после каждой сборки сохраняет в `art/renders/<id>/`:

| Файл | Что | Зачем |
|---|---|---|
| `side.png`, `front.png`, `rear.png`, `top.png` | Ортографические виды, Workbench, силуэт и контур | Пропорции, сравнение со схемой силуэта |
| `three_quarter_front.png`, `three_quarter_rear.png` | Перспектива 3/4, Cycles 64 сэмпла + шумодав, студийный свет | Общее впечатление |
| `night.png` | Ночная улица, мокрый асфальт, фары включены | Как будет выглядеть в игре |
| `uv_check.png` | Шахматка на `uv1` | Ливреи не растянуты |
| `kits.png` | Сетка 2×2: база и три кита | Киты сидят без щелей |
| `lod.png` | LOD0, LOD1, LOD2 рядом | Силуэт держится на расстоянии |

Разрешение 1024 px, превью собирается в одну картинку-лист `sheet.png` — её удобно смотреть с телефона.

### 5.6 Чек-лист приёмки машины

1. Силуэт и пропорции сразу читаются как нужный типаж (Claude описывает словами, что видит на `side.png` и `three_quarter_front.png`).
2. Все пункты `differences` видны на рендерах; машину нельзя принять за оригинал на скриншоте. Сомнение → добавить отличие.
3. Нет логотипов, надписей, узнаваемых фирменных решёток.
4. Колёса стоят в центре арок, зазор равномерный, посадка как у спорткара.
5. Нет дыр, вывернутых нормалей, мерцающих наложений (`checks.py` = 0 ошибок).
6. Бюджеты полигонов и текстур соблюдены, LOD есть, валидатор `pnpm art:validate` зелёный.
7. Шахматка на `uv1` без растяжений на боках и капоте.
8. Все 3 кита садятся без щелей.
9. В игре: 30 fps на телефоне с 8 машинами в кадре (пресет `low`).
10. Владелец утвердил `sheet.png`.

### 5.7 Порядок машин

Сначала одна машина целиком — она отлаживает весь генератор. Потом остальные, от простых форм к сложным:

1. Японское турбо-купе (дух R34) — эталон, на нём строится весь конвейер.
2. Немецкий горячий хэтч (дух Golf GTI) — простая форма.
3. Раллийный седан 4WD (дух Evo/Impreza).
4. Американский маслкар (дух Mustang).
5. Японское купе (дух Supra Mk4) — сложные плавные формы.
6. Роторное купе с подъёмными фарами (дух RX-7) — анимация фар.
7. Немецкий бизнес-седан (дух M5).
8. Горячий хэтч с антикрылом (дух Civic Type R).
9. Японский суперкар 4WD (дух GT-R R35).
10. Заднемоторное спорткупе (дух 911 GT3) — самый узнаваемый силуэт, нужно особенно аккуратно с отличиями.
11. Итальянский клиновидный суперкар.
12. Электро-гиперкар.

## 6. Город

Принцип: Блендер делает **библиотеку модулей** (здания, реквизит, ориентиры) и общие атласы текстур. Расстановку по улицам делает существующий инструмент `tools/osm-to-city` (задача 10.1 в PLAN_V2) — одинаковые модули рисуются экземплярами, это намного быстрее на телефоне, чем уникальная геометрия.

### 6.1 Атласы — `trim_sheet.py`

- Один атлас фасадов 2048×2048 на город: полосы бетона, кирпича, штукатурки, стекла, карнизов, балконных ограждений, витрин. Генерируется шейдерными нодами и запекается.
- Атлас ночных окон 1024×1024 с эмиссией: 16 вариантов окон (тёмное, тёплый свет, холодный свет, телевизор, шторы). Каждое окно здания получает UV на случайную ячейку — город «живой» без тысяч источников света.

### 6.2 Модули зданий — `build_modules.py`

Каждый тип — параметрический генератор (этажи, пролёты, высота этажа, тип окна, балконы, карниз, первый этаж-витрина, крыша), модуль ставится на прямоугольный участок.

| Набор «Москва-зима» (первый) | Набор «Токио-неон» (второй) |
|---|---|
| Сталинка 7–9 этажей с карнизом и пилястрами | Узкий высокий дом 6–12 этажей с вертикальными вывесками |
| Панелька 9 и 16 этажей с лоджиями | Офисная башня со сплошным остеклением |
| Хрущёвка 5 этажей | Дом с наружной лестницей и кондиционерами |
| Стеклянная башня делового центра | Торговый центр с медиафасадом |
| Торговый центр, заправка, павильон | Магазин 24/7, автомат с напитками, кафе |
| Церковь-силуэт (стилизованная, без копирования конкретного храма) | Храмовые ворота-силуэт (стилизация) |

Варианты внутри типа — разные параметры одного генератора (не отдельные модели): 4–6 вариантов на тип. Бюджет: 2–5 тыс. треугольников на модуль, LOD1 — коробка с атласом.

### 6.3 Реквизит — `props.py`

Фонари (2–3 типа на город, с точкой крепления «пятна» света), остановки, ограждения и отбойники, светофоры, дорожные знаки (общие формы без текста), рекламные щиты и вывески с **вымышленными брендами** (Claude генерирует простые логотипы-формы и названия), сугробы и наледь (Москва), торговые автоматы и бумажные фонари (Токио), припаркованные машины — LOD2 наших же машин.

### 6.4 Ориентиры — `landmarks.py`

3–5 на город, **стилизованно**, по мотивам: например, для «Москвы» — высотка со шпилем, телебашня, мост с арками; для «Токио» — красно-белая башня, перекрёсток с экранами, высокий мост. Не копировать реальные здания точно: упрощённая форма, другие пропорции деталей, своя подсветка. Список и координаты — в `art/specs/city/<kit>.json`.

### 6.5 Чек-лист приёмки набора зданий

1. Рендер «улица ночью» (`art/renders/city_<kit>/street_night.png`) читается как нужный город за 2 секунды.
2. Ни одной реальной вывески, логотипа, точной копии здания.
3. Модули стыкуются без щелей, окна не мерцают.
4. Бюджет: блок 256 м ≤ 3 МБ, ≤ 80 draw calls в `low`.
5. 30 fps на телефоне в свободном заезде.
6. Владелец утвердил рендеры.

## 7. Трассы и карты

Сами трассы уже строятся кодом игры из сплайнов (`packages/shared/src/tracks`). Блендер добавляет то, что делает их красивыми.

### 7.1 Оформление — `dressing.py`

Библиотека элементов: бетонные блоки, отбойники, шинные стенки, сетчатые заборы, трибуны, арка старта/финиша с вымышленным названием гонки, баннеры спонсоров (вымышленных), конусы, мачты освещения, тоннель (модульные секции), мост (пролёты). Игра расставляет их вдоль сплайна по правилам (через N метров, на внешней стороне поворота и т. п.) — правила задаются в JSON трассы.

### 7.2 Рельеф для горного перевала — `terrain.py`

1. Игра выгружает сплайн трассы в `art/specs/track/<id>.json` (новая команда `pnpm track:export <id>`).
2. Скрипт строит сетку рельефа вокруг дороги: шум + «эрозия» модификаторами, дорога врезается в склон, обочины и откосы.
3. Скалы и деревья — экземплярами (2–3 модели скал, 3 модели сосен).
4. Экспорт блоками 256 м, как город. Коллизия — упрощённая сетка `_collision`.

### 7.3 Карта для меню и мини-карты

`render.py` рендерит вид сверху трассы и района в стилизованном виде (тёмный фон, светящаяся линия трассы) → `apps/client/public/maps/<id>.png` для экрана выбора трассы.
