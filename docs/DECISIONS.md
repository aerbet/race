## Архитектура

- 2026-11-25 — Пакеты рабочего пространства подключаются исходниками (`main: src/index.ts`), без отдельной сборки: Vite, Vitest и tsx понимают TS напрямую. Меньше шагов сборки — быстрее итерации.
- 2026-11-25 — Один корневой `vitest.config.ts` собирает тесты всех пакетов: `pnpm test` = один прогон.
- 2026-11-25 — Трасса задаётся сплайном Catmull-Rom (`packages/shared/src/tracks`), из неё строятся осевая (шаг 2 м), чекпоинты, решётка, стены и трамплины. Полигон 0.5 и формат 2.1 — одна система, полигон — это кольцевая трасса.
- 2026-11-25 — Raycast vehicle на Rapier: кузов — твёрдое тело с заданной массой/инерцией (`setAdditionalMassProperties`), колёса — лучи `castRayAndGetNormal`. Боковая сила ограничена «силой, гасящей боковую скорость за шаг» — нет дрожания на малой скорости при 60 Гц. Продольная — тяга по моменту с ограничением кругом трения и кривой по коэффициенту проскальзывания (без модели вращения колеса — аркада).
- 2026-11-25 — Сила шин прикладывается в точке, поднятой на 60 % к центру масс: меньше кренов, мягче поведение, типичный аркадный приём.
- 2026-11-25 — Автомат: задний ход включается тормозом на месте, газ работает как тормоз (аркадная схема).
- 2026-11-25 — Пресет качества по умолчанию: телефон → `low`, ПК → `high`; `?q=low|high` переопределяет. На `low` нет теней, bloom, размытия, линий скорости, меньше частиц и зданий.
- 2026-11-25 — Свет фонарей на `low` и `high` — аддитивные «пятна» на асфальте вместо настоящих точечных источников: ночная картинка почти бесплатно.
- 2026-11-25 — Кузова — собственная экструзия бокового профиля (два профиля: «нулевые» и «2026»), без внешних моделей.
- 2026-11-25 — Ввод квантуется до байта прямо при сэмплировании, поэтому запись ввода воспроизводит ровно те значения, что видела физика.
- 2026-11-25 — Удержание дрифта — PD-регулятор угла заноса (kp = `driftHold.strength`, kd ≈ 1,8·√kp). Цель угла зависит от руля: в сторону дрифта — ближе к `maxAngleDeg`, нейтрально — к середине; руль прямо/против на 0,15 с — выход. Разворот разрешён только при «явной ошибке»: ручник + полный руль в сторону заноса за пределом угла.
- 2026-11-25 — В дрифте скорость не «съедается»: сила вдоль скорости возвращает `speedKeep` доли потерь от боковых сил, а вектор скорости подкручивается к носу без изменения модуля.
- 2026-11-25 — Ручник/занос не роняют обороты и не вызывают понижение передачи — иначе машина «садилась» на первую и терялась скорость.
- 2026-11-25 — Нитро в физике: +`boost` к тяге (не режется лимитером), расход за `capacity` секунд; заряд от дрифта (|β|>15°, >40 км/ч), от прыжка (при приземлении, если полёт >0,35 с), от обгона — метод `addNitro()` вызывает гоночная логика.
- 2026-11-25 — `Sim.tick` квантует любой ввод (игрок, бот, сеть) до байта: физика видит ровно то, что попадает в запись. Тест: круг бота при 30/60/144 fps рендера и повтор записи дают одинаковое время до шага.
- 2026-11-25 — Боты (`packages/physics/src/bot.ts`) — в пакете физики, чтобы их могли гонять тесты и сервер. Линия: осевая + смещение внутрь поворота + своя полоса; скорость — минимум по «допустимой скорости поворота √(μg/k)» на дистанции торможения.
- 2026-11-25 — Гоночная логика (`packages/shared/src/race/tracker.ts`) общая для клиента и сервера, время — в шагах физики. Прогресс для позиций зажат между соседними чекпоинтами — срезка не даёт выигрыша.
- 2026-11-25 — Звук двигателя: 4 «собственные записи» — петли по 1 с, синтезируемые при старте в `OfflineAudioContext` (гармоники частоты зажигания + неровность цилиндров + шум), характер по типу мотора (I4/V6/V8/роторный/электро). Кроссфейд равной мощности между двумя ближайшими по оборотам, высота — `playbackRate`. Без внешних аудиофайлов → нет вопросов с лицензиями, 0 байт к загрузке.
- 2026-11-25 — Призраки: 20 Гц, 14 байт на кадр (int16: позиция с шагом 4 см от первой точки, кватернион ×32767), base64 в localStorage по ключу трасса+машина. Сохраняется лучший круг.
- 2026-11-25 — Режимы: круг (полигон, 3 круга, боты), спринт (отдельная открытая трасса), дрифт (2 круга, очки), на время (против призрака), свободная езда. Игрок стартует последним при гонке с ботами. После финиша машиной игрока управляет бот.
- 2026-11-25 — Обгон заряжает нитро обгоняющему (событие `overtake` трекера).
- 2026-11-25 — Слепой тест: машины под буквами в случайном порядке для каждого тестера, минимум 60 с езды, 5 вопросов 1–5, результаты в localStorage + выгрузка JSON со средними по машинам (`?blind`).
- 2026-11-25 — HUD — собственный стиль: скошенные панели, циан/маджента, тахометр-дуга на canvas, мини-карта из осевой трассы.

## Фаза 3 — онлайн

- 2026-11-25 — **3.1 Сервер: чистый `ws`, не Colyseus.** Аргументы: (1) свой бинарный протокол на DataView уже нужен по плану (3.2) — состояние Colyseus (schema-сериализация) дублировало бы его; (2) гоночная логика и физика ботов уже есть в общих пакетах, от фреймворка нужен только транспорт; (3) меньше зависимостей и «магии», полный контроль над тиком 30 Гц и порядком обработки; (4) комнаты/матчмейкинг для 8 игроков — ~150 строк. Минусы: переподключение и масштабирование на несколько процессов — пишем сами (позже, при необходимости).
- 2026-11-25 — Модель авторитета: клиент считает свою машину сам (мгновенный отклик, «предсказание» без отката), шлёт состояние 30 Гц; сервер проверяет правдоподобие (скорость, перемещение, часы клиента, время участка), ведёт старт, чекпоинты, финиш и порядок. Отклонённый пакет → `Correction` с последним принятым состоянием, клиент мягко подтягивается. 90 отклонений подряд или 2 «невозможных» участка → сход (DNF).
- 2026-11-25 — Боты онлайн считаются на сервере (Rapier в Node), люди в серверной физике — кинематические «тени» (`Sim.addProxy`), поэтому боты их объезжают и толкаются с ними.
- 2026-11-25 — Время гонки — шаги сервера (60 Гц) → спорных финишей нет: порядок решает сервер. Тест: 4 клиента, 150 мс, джиттер 25 мс, 2 % потерь — порядок совпадает с локальными временами клиентов, все получили одинаковые результаты.
- 2026-11-25 — Симулятор плохой сети моделирует TCP: потеря = задержка на повтор (RTO) с блокировкой очереди, порядок сохраняется. Клиент: `?lag=150&jitter=30&loss=2`; сервер: `NET_LAG`, `NET_JITTER`, `NET_LOSS`.

## Фаза 4 — город

- 2026-11-25 — **4.1 `tools/osm-to-city`**: Overpass JSON → проекция в метры (X — восток, Z — юг) → дороги по классам (ширина из `lanes` или по классу) с упрощением Дугласа–Пекера (замкнутые кольца делятся пополам) → здания (высота: `height` → `building:levels`×3,2 м → по типу) → блоки 256 м → `.glb` + `city.json` (дороги, коллайдеры зданий, трассы). glTF пишем своим минимальным писателем (~100 строк) — без зависимостей. Атрибуция «© участники OpenStreetMap (ODbL)» записывается в city.json и показывается в HUD.
- 2026-11-25 — Сеть: Overpass из облачной среды пока недоступен (прокси рвёт соединение, хост добавлен в окружение). Поэтому в игре сейчас **процедурный вымышленный район «по мотивам Москвы»** (`--synth`: кольцевой бульвар, 7 радиальных проспектов, переулки, периметральная застройка 4–12 этажей и редкие башни). Реальный район: `pnpm --filter osm-to-city build -- --bbox s,w,n,e --id … --name …` на машине с интернетом — формат тот же.
- 2026-11-25 — **4.2** Застройка: экструзия контуров, палитра фасадов (охра, беж, серый панельный, кирпич, белый), окна — общая текстура 8×8 с UV «1 единица = окно 4 м × этаж», часть окон светится (emissive). Неоновые вывески ставятся процедурно на длинные фасады крупных зданий.
- 2026-11-25 — Коллайдеры зданий: почти прямоугольный контур (заполнение ≥ 85 %) → один ориентированный бокс, иначе — тонкие стенки по рёбрам (L-образные дома не перекрывают улицы).
- 2026-11-25 — Здания, попадающие в коридор трассы (сплайн срезает углы перекрёстков), инструмент удаляет при сборке.
- 2026-11-25 — **4.3** Стриминг: рендер грузит блоки в круге радиусом 2 (low) / 3 (high) блока от камеры, ближние первыми, не более 3 загрузок одновременно; дальние выгружаются. Физика держит коллайдеры блоков 3×3 вокруг каждой машины (обновление раз в 10 шагов). Размер района ~0,9 МБ glb — далеко в пределах бюджета 80 МБ на страну. KTX2/meshopt не подключены: текстур в блоках нет (окна — одна процедурная текстура), а геометрия и так мала; вернуться при появлении моделей от художника.
- 2026-11-25 — **4.4** Ночь всегда; погода: сухо / дождь (мокрый асфальт с отражениями на high, капли) / снег (слякоть на дороге, снег на земле и крышах, снегопад, ближе туман). Сцепление: `WEATHER_GRIP` 1 / 0,86 / 0,72 — множитель шин (`Vehicle.surfaceGrip`); тест: тормозной путь в снегу длиннее > 15 %.
- 2026-11-25 — **4.6** Три трассы по улицам района: кольцо по бульвару, спринт «проспект → бульвар → проспект», дрифт-сектор через центральную площадь. Тесты: средний отход осевой трассы от улиц < 4 м, бот проходит каждую трассу среди зданий без сбросов и касаний стен. На улицах — неоновые шевроны направления и столбы чекпоинтов.
- 2026-11-25 — **4.5 Свободная езда** (протокол v2): зона города до 16 игроков (`MAX_FREEROAM`), при заполнении — новая зона. Сервер шлёт снимки 30 Гц, проверяет числа/скорость/перемещение; сброс разрешён только на улицу (`distanceToRoad`). Часы клиентов в свободной езде не сверяются (игроки заходят в разное время) — только порядок шагов.
- 2026-11-25 — Вызов на гонку фарами: H мигает фарами (флаг `CarFlags.Lights` виден другим) и шлёт `Challenge` ближайшему игроку в радиусе 45 м; сервер пересылает `ChallengeInvite` (действует 12 с), Y/N или кнопки — ответ. При согласии сервер создаёт приватную комнату на той городской трассе, чья решётка ближе к вызывающему, без ботов (`minRacers: 2`), 1 круг; оба клиента входят с авто-«готов». После гонки — снова онлайн-меню.
- 2026-11-25 — Сервер читает города из `apps/client/public/cities/*/city.json` при старте и регистрирует их трассы — онлайн-гонки на городских трассах работают так же, как на полигоне (в `Welcome` передаётся `city`).

## Фаза 5 — API и метаигра

- 2026-11-25 — **5.1 Вход:** email + пароль (BCrypt) и Telegram Login Widget (проверка подписи HMAC-SHA256 от SHA256(токена бота), срок 24 ч). VK ID отложен: нужна регистрация приложения VK и OAuth-редирект — добавим, когда будет домен. JWT HS256 (`spring-boot-starter-oauth2-resource-server`, Nimbus), секрет только из `JWT_SECRET`, срок 7 дней. Новый игрок получает 20 000 кредитов и первую машину (Kestrel S2).
- 2026-11-25 — Схема БД — Flyway (`V1__init.sql`), Hibernate только валидирует (`ddl-auto: validate`).
- 2026-11-25 — **5.2 Тюнинг:** общая таблица `packages/shared/src/tuning/parts.json` (8 категорий × 4 уровня, цены, эффекты; «нулевые» получают 100 % эффекта, «2026» — 60 %). Клиент применяет её к конфигу физики (`applyTuning`), API считает PI по той же формуле (`PiCalculator`). Совпадение языков проверяет общий файл `pi-fixtures.json` (тест TS пишет/сверяет, тест Java сверяет). Классы: D < 400 ≤ C < 500 ≤ B < 600 ≤ A < 700 ≤ S. Сток — D; полный тюнинг: «нулевые» → A, «2026» → B.
- 2026-11-25 — Визуальный тюнинг: слоты paint/neon (#rrggbb), rims/spoiler/bumper/vinyl (id варианта); сервер валидирует формат.
- 2026-11-25 — **5.3 Экономика:** баланс меняет только `EconomyService.apply` (кошелёк блокируется `SELECT … FOR UPDATE`, затем проверка ключа идемпотентности — параллельные запросы с одним ключом списывают один раз, тест на 8 потоков). Каждая операция — строка журнала `ledger` с балансом после. Покупка = списание + выдача в одной транзакции; повтор ключа возвращает ту же покупку.
- 2026-11-25 — Тесты API — на настоящих PostgreSQL и Redis (Testcontainers не используем: в облачной среде нет Docker). Локально: база `racer_test`, Redis db 1, см. README.

- 2026-11-25 — **5.5 Рейтинг:** многопользовательский Эло — попарные сравнения по местам, K = 32/(n−1), сход = общее последнее место (ничья между сошедшими). Рейтинг хранится по (игрок, сезон, класс машины); каждый получает изменение в классе **своей** машины (класс берётся из гаража API по id машины, а не со слов клиента). Сезоны — таблица `seasons`, рейтинг пишется в активный.
- 2026-11-25 — Итоги онлайн-гонок: сервер гонок проверяет JWT игрока сам (HS256, общий `JWT_SECRET`, без зависимостей) и после финиша шлёт `POST /internal/race-results` (ключ `INTERNAL_KEY`, идемпотентно по `race_id`). Награды кредитами — всем вошедшим финишировавшим (3000/2000/1500/800), рейтинг — только в открытых комнатах от двух игроков с аккаунтом. Гости играют как раньше, без наград. Протокол v3: в `Hello` добавлены токен и id машины из гаража.
