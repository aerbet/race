# PLAN_V3 — готовность к запуску

PLAN_V2 и этапы Блендера B0–B7 закрыты (см. `docs/HANDOFF_2026-11-27.md`). Владелец попросил продолжать без остановок, нового плана не прислал. Поэтому эта фаза закрывает то, что мешает выпустить игру и не требует решений владельца: выкладку, проверки в CI, Telegram Mini App и надёжность оплат. Решения владельца (хостинг, домен, бот, юрлицо, цены) здесь не принимаются. Всё настраивается переменными окружения, а значения по умолчанию безопасны.

## Фаза 11. Запуск

- [x] **11.1 Docker:**
  - образы `api` (Spring Boot), `race-server` (Node) и `web` (статика клиента + nginx-прокси `/api`, `/webhooks`, `/ws`);
  - `deploy/docker-compose.yml` с PostgreSQL и Redis;
  - `deploy/.env.example` со всеми переменными без значений-секретов;
  - `docs/DEPLOY.md` — инструкция для владельца.
  - Клиент в продакшене обращается к API и серверу гонок через тот же домен (без портов 8080 и 2567).
- [x] **11.2 CI** (GitHub Actions):
  - lint, prettier, typecheck, тесты TS;
  - Java-тесты с PostgreSQL и Redis в services;
  - сборка клиента;
  - дымовые e2e.
- [x] **11.3 Telegram Mini App:**
  - официальный скрипт `telegram-web-app.js`;
  - вход по `initData` (проверка HMAC по правилам Mini App) — `POST /api/auth/telegram-webapp`;
  - автоматический вход при запуске внутри Telegram;
  - язык из Telegram, тема и отступы безопасной зоны;
  - кнопка «Назад» Telegram закрывает экраны.
- [x] **11.4 Надёжные оплаты Stars:** `successful_payment` сохраняет `telegram_payment_charge_id`. Подтверждение не зависит от «последних 100 транзакций»: сверка ищет транзакцию по id с постраничным проходом.
- [x] **11.5 Настройки в профиле:** язык, свои YouTube-плейлисты и режим стримера хранятся в аккаунте (`GET/PUT /api/me/settings`) и переезжают между устройствами; без входа — как раньше, в браузере.
